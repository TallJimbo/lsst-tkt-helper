## Problem

Global agent instructions are authored in this repo but delivered per-harness, one
file each, with no shared layer:

- `tkt install-zed-agent` symlinks `~/.config/zed/AGENTS.md` → `harnesses/zed/rules.md`
  (a live symlink; `install.py:152–156`).
- `tkt install-opencode-agent` installs no global instructions file at all. Its
  destination, `~/.config/opencode/AGENTS.md`, is a **broken symlink** on real
  hosts — it still points at `harnesses/shared/sandbox-agents.md`, a file that
  never landed on `main` (it exists only on `af62cba`/`b3baef9`, on an unreached
  lineage), so a main-based install leaves the link dangling.
- Cross-harness rules (things true for both Zed and OpenCode agents) have no home:
  they get duplicated into both harness layers or dropped.

The goal is a shared layer plus a harness-specific layer, merged into each
harness's global-instructions file at install time:

```
harnesses/shared/AGENTS.md      NEW  cross-harness rules
harnesses/opencode/AGENTS.md    NEW  OpenCode-specific extras
harnesses/zed/rules.md          kept Zed dispatch table (unchanged, still a source)

tkt install-opencode-agent → ~/.config/opencode/AGENTS.md = shared + opencode
tkt install-zed-agent      → ~/.config/zed/AGENTS.md      = shared + zed/rules.md
```

## Decisions

### 1. Delivery: generated concatenation at install time

A symlink cannot merge two files, so both installers write a **plain generated
file**. This deliberately changes Zed's semantics from a live symlink to a copy:
edit a source, then re-run `tkt install-*-agent`. Considered and rejected:

- **Commit merged copies** into the repo — two derived files to keep in sync by hand.
- **Harness-native includes** — Zed has no include mechanism, so the pattern could
  not be symmetric.

### 2. Order: shared first, harness file second

Sections joined by **one blank line**; no artificial section headers and **no
"Generated by" marker comment** (the human removed that requirement — no
provenance stamp and no edit-protection wanted).

### 3. Clobber policy = the plugin-copy rule

| State at `dest` | Behavior | Log |
| --- | --- | --- |
| symlink (correct, stale, or broken) | replace | `Replacing symlink …` (warning) |
| real file, **identical bytes** | leave untouched | `OK: … up to date` (info) |
| real file, **different bytes** | replace | `Replacing stale generated copy …` (warning) |
| **not a file** (e.g. a directory) | refuse, keep | `Refusing to replace non-file …` (warning) |
| absent | create | `Writing …` (info) |

Last write wins: an edited installed copy is reverted at the next install. The
symlink row is what cleans the broken `~/.config/opencode/AGENTS.md` link on
existing hosts. The neutral symlink wording (rather than "stale") is deliberate:
a legacy install's link to `rules.md` was *correct*, and it must still be replaced.

Two choices inside the helper, surfaced in review and adopted:

- **`os.chmod(tmp, 0o644)`** before `os.replace`. `tempfile.mkstemp` creates
  `0600`; without this the global instructions file is owner-only, and nothing
  else in this repo sets file modes.
- **The non-file refusal** extends the handoff's policy table, which covered
  symlink / real file / absent but not a directory at `dest` (a plausible state).
  This mirrors `_ensure_link`'s existing "Refusing to replace non-symlink" rather
  than letting `os.replace` raise `IsADirectoryError`.

### 4. Missing sources are skipped

Each source is included iff `os.path.isfile`; a missing one is logged at info and
skipped (so `install-*-agent` still works in a partial/fake tree). If **no**
source exists, nothing is written to `dest`.

Because absence is a supported state, a harness's `AGENTS.md` may legitimately not
exist while it still appears in `harnesses/README.md`'s layout block and in the repo
`AGENTS.md` integration sections. Those entries name a **slot** — where harness-specific
rules go when written — not a claim that the file is present. Removing them because the
file is absent would erase the pointer to that slot.

### 5. The merge is heading-blind; no heading contract

Concatenation strips outer whitespace and joins; it never parses markdown. A
"smart" merge that demoted `#`→`##` for non-first sources was considered and
rejected: `#` is also a shell comment, so a demoter must be fence-aware, and
fenced `bash` blocks (`ruff check .`-style gate blocks) are exactly what shared
content will contain.

Consequences accepted as facts, **not codified as an authoring contract** (the
human chose to leave heading style free — so no heading rules are added to
`harnesses/README.md` or the stub comments):

- Heading levels are final at authoring time; nothing repairs them afterward.
- With no artificial section headers, a source's own H1 is the merged document's
  only title for that section.
- A skipped source's headings are simply absent from the output.

### 6. Sandbox untouched

Restricted sandbox runs get a tmpfs `$HOME`, so the host global file never leaks
in; the sandbox's project `AGENTS.md` comes from `tkt/AGENTS.md.in` rendering
(`sandbox.py`) — a separate layer, unchanged here.

## Interface stub

`tkt/install.py` gains one private helper, called by both installers (the
`_install_plugin` machinery the original handoff cited as the atomic-write
precedent **no longer exists** — deleted at the base commit; the pattern is
written fresh):

```python
def _install_merged_agents_md(sources: list[str], dest: str, *, dry_run: bool) -> None:
    """Concatenate the existing ``sources`` (in order) into ``dest``.

    Sources are stripped of surrounding whitespace, joined by one blank line,
    and terminated by exactly one newline.  A symlink at ``dest`` (correct,
    stale, or broken) is replaced; a real file with identical bytes is left
    untouched; a real file whose bytes differ is replaced with a warning.
    Writes atomically; writes nothing when no source exists.
    """
```

Design-critical body (the clobber policy above is what the plan phase must
preserve):

```python
    sections: list[str] = []
    for src in sources:
        if not os.path.isfile(src):
            logging.info(f"Skipping missing agents source {src}")
            continue
        with open(src, encoding="utf-8") as f:
            sections.append(f.read().strip())
    if not sections:
        logging.info(f"No agents sources present; leaving {dest} alone")
        return
    data = ("\n\n".join(sections) + "\n").encode("utf-8")
    if os.path.islink(dest):
        logging.warning(f"Replacing symlink {dest} -> {os.readlink(dest)}")
    elif os.path.lexists(dest):
        if not os.path.isfile(dest):
            logging.warning(f"Refusing to replace non-file {dest}")
            return
        with open(dest, "rb") as f:
            if f.read() == data:
                logging.info(f"OK: {dest} up to date")
                return
        logging.warning(f"Replacing stale generated copy {dest}")
    logging.info(f"{'Would write' if dry_run else 'Writing'} {dest}")
    if dry_run:
        return
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(dest), prefix=".AGENTS.md.")
    try:
        with os.fdopen(fd, "wb") as f:
            f.write(data)
        os.chmod(tmp, 0o644)
        os.replace(tmp, dest)
    except BaseException:
        os.unlink(tmp)
        raise
```

Requires a new `import tempfile` in `tkt/install.py`.

**Normalization is byte-exact and load-bearing for idempotence:** each source is
`.strip()`ed, joined with `"\n\n"`, plus one trailing `"\n"`. A source ending in
zero or five newlines yields identical bytes, so the "identical bytes → leave
alone" comparison is stable across re-runs.

## Drift since the handoff

Recorded because the handoff's references are now wrong, though its design is not:

1. `tkt/install.py` no longer contains `_install_plugin` (the cited
   `mkstemp`+`os.replace` precedent): the base commit `49aa50a` deleted the whole
   plugin-copy machinery (`PLUGIN_NAMES`, `plugin_source`, `_install_plugin`,
   `_install_plugin_dir`, `_plugin_tree`). The atomic-write decision stands; the
   precedent is gone. **This is also why the branch must be cut from `49aa50a`,
   not `bcbbbbf`** — the drift sits in the file being edited.
2. The handoff's docs list omitted `tkt/_cli.py`'s help strings.
3. The handoff attributes the `sandbox-agents.md` deletion to `af62cba`/`b3baef9`.
   Verified against git: those two commits are the ones that created and modified
   that path, and **neither is an ancestor of `main`** — so the file never landed
   on `main`, and no reachable commit deleted it. (An earlier revision of this
   spec blamed `653a601`, which does not touch the path at all; that claim was
   wrong and is corrected here.) The host's broken link is a residue of an
   install made from the unreached lineage. Immaterial to the design: the symlink
   row of the clobber policy replaces any symlink generically.

Also note for the plan phase: **one existing test inverts** (see Testing), so this
is not purely additive.
