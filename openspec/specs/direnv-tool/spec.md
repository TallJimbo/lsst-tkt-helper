# direnv-tool

## Purpose

A `DirEnv` tool that generates a `.envrc` file in the workspace capturing the
full conda/EUPS environment from a pristine subprocess, so direnv can restore
the environment when entering the workspace. It is regenerated by workspace
commands (`new`, `update`, `upgrade-metapackage`).

## Requirements

### Requirement: DirEnv tool class

`tkt` SHALL provide a `DirEnv` class subclassing `Tool` (in `tkt/direnv.py`),
with `from_json_data` and `write` matching the `Tool` ABC, that produces a
`.envrc` file in the workspace directory. `from_json_data` SHALL accept optional
`scripts` and `env` lists and reject any other keys.

#### Scenario: Tool is discoverable via the Tool ABC

- **WHEN** `DirEnv.from_json_data` is called with the tool's configuration
- **THEN** it returns a `DirEnv` instance and rejects any unexpected
  configuration keys

#### Scenario: Config with scripts and env

- **WHEN** `DirEnv.from_json_data` is called with `scripts` and `env` lists
- **THEN** the returned `DirEnv` uses those lists, and omitting either defaults
  it to an empty list

### Requirement: Capture the full conda/EUPS environment from a pristine subprocess

`DirEnv.write` SHALL run a subprocess shell in the workspace directory with a
mostly-pristine environment that propagates only the configured `env` var names
from the parent (plus essential base vars), sources each configured `scripts` file
in order, then runs `setup -r .` and captures the resulting environment. It SHALL
write the complete captured environment to the workspace's `.envrc` as `export`
lines. The implicit delta against the parent shell is left to direnv; `DirEnv`
does not compute a diff.

#### Scenario: Full environment written on workspace creation

- **WHEN** `tkt new` is run with `direnv` in the tool list and a
  `loadLSST.*` script configured
- **THEN** a `.envrc` file exists in the workspace directory and contains
  `export` lines reflecting the conda/EUPS environment and workspace setup after
  the scripts and `setup -r .`

#### Scenario: Every propagated and added variable is exported

- **WHEN** the capture subprocess runs
- **THEN** the `.envrc` contains `export` lines for the base vars and configured
  parent envvars that were propagated into the subprocess, as well as for every
  var added or changed by the scripts and `setup -r .`, so the whole captured
  environment is present and direnv computes the delta against the parent shell

#### Scenario: Only configured parent envvars are propagated

- **WHEN** the capture subprocess runs
- **THEN** the subprocess env contains only the configured `env` var names copied
  from the parent (plus essential base vars), not the full parent environment

#### Scenario: No captured variables leaves the file unchanged

- **WHEN** the captured environment is empty
- **THEN** the tool leaves any existing `.envrc` untouched and writes no file

#### Scenario: Subprocess failure propagates

- **WHEN** the subprocess setup command exits nonzero or a configured script path
  does not exist
- **THEN** `DirEnv.write` raises an error and does not write a stale `.envrc`

### Requirement: Regenerated by workspace commands

`DirEnv` SHALL be invoked by the standard tool-writing path, so its `.envrc` is
regenerated by `tkt new`, `tkt update`, and `tkt upgrade-metapackage`.

#### Scenario: Refresh on update

- **WHEN** `tkt update` is run with `direnv` in the tool list
- **THEN** the `.envrc` is regenerated from the current environment

#### Scenario: Default tool list includes direnv

- **WHEN** `tkt new` is run without `--tool`
- **THEN** `direnv` is among the tools applied to the workspace
